Limitations

  • Payment verification is manual (screenshot review) — introduces hours of latency, single point of failure.
  • System depends entirely on Telegram — no Telegram account, no access; outages affect availability.
  • Images stored as base64 in PostgreSQL (not object storage) — 1MB practical limit per image.
  • No automated authenticity checks on uploaded IDs — relies on admin visual inspection.
  • Currently supports only the Ethiopian market and three languages.
  • No in-app dispute resolution mechanism — handled via external Telegram chat.
Temariware — Senior Project Defense 8 / 27
  • Manual payment verification is the biggest limitation — mitigated in v2 with Chapa API.
  • Telegram dependency is accepted as a trade-off — the platform's reach justifies it.
  • Base64 image storage is fine for current scale but should move to S3 / Supabase in v2.
  • ID verification stays manual in v1 — admin review window is 24h SLA.
  • Dispute resolution via Telegram is acceptable for v1; will be in-app in v2.
