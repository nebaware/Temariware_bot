Software Architecture

  • Selected style: Layered Architecture with four layers — Presentation, Application, Domain, Persistence.
  • Presentation Layer: React 19 components (Mini App views).
  • Application Layer: Next.js API routes (controllers).
  • Domain Layer: Prisma models + business logic.
  • Persistence Layer: PostgreSQL on Neon (Frankfurt, eu-central-1).
  • Chosen for clear separation of concerns, Next.js convention alignment, team familiarity.
Alternatives considered: Microkernel (too complex), Event-Driven (unnecessary complexity), Serverless-First (already adopted at deployment). Full comparison in Chapter 3, Table 3.1.
- Four layers map cleanly to Next.js folder conventions (app/, api/, lib/, prisma/). - Layered over microservices because the team is small and the domain is bounded. - Persistence layer is swappable — Neon Postgres today, could be Supabase tomorrow. - Serverless-First was redundant: Vercel already enforces it at deployment. - Reference Table 3.1 in the document for the full architecture trade-off matrix.
