Detailed Design

  • Design-Level Class Diagram: refines conceptual model with attributes, operations, visibility (Figure 3.5).
  • Collaboration Diagrams: Apply to Job, Post Job and Pay, Approve Payment and Hire (Figures 3.6–3.8).
  • State Chart Diagram: Application lifecycle — PENDING → ACCEPTED → PAYMENT_PENDING → HIRED (or REJECTED/CLOSED) (Figure 3.9).
  • User Interface Diagrams: 6 views — Home, Job Detail, Post Job, Applications, Profile, Admin (Figures 3.10–3.15).
  • Class Type Architecture: Entity (7 classes), Boundary (7 classes), Control (6 classes) — ECB pattern.
  • All design artefacts provide a complete blueprint for implementation handoff.
- Class diagram is the bridge between conceptual model and Prisma schema. - Collaboration diagrams clarify who initiates each cross-layer call. - State chart drives the Application status enum and transitions at API layer. - UI diagrams were the most useful artefact during implementation handoff. - ECB pattern keeps entity, boundary, and control logic cleanly separable.
